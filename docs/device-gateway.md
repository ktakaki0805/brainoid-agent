# Cloud device WSS gateway

BA-DEV-03 implements the cloud connection boundary for FR-003/014 and T-004/023/024. The route is `WSS /v1/devices/{device_id}/connect`. The supported server entrypoint is `python -m brainoid_api` (also `mise run dev-api`); TLS termination belongs to the deployment. This ticket does not deploy Cloud Run, implement a Pi client, snapshot sync, command dispatch, or execution grants.

## Admission and frames

Send exactly one `Authorization: Bearer <dedicated device access token>` header and exactly the `brainoid-agent.device.v1` subprotocol. User credentials, duplicate authorization headers, all query strings, cookies, and extra subprotocols are refused. The route device ID and hello device ID must equal the verified token subject. The server requires hello within 10 seconds, then returns hello_ack with the durable generation, a 15 second heartbeat interval, lease expiry, server time, and `snapshot_required: true`. Snapshot implementation belongs to BA-DEV-04; the ack does not claim that snapshot sync already exists.

Text JSON frames have a 64 KiB UTF-8 limit, enforced both by the supported transport and the application. Binary, malformed UTF-8/JSON, duplicate JSON keys, nonfinite numbers, invalid UUID/date-time formats, extra fields, and unknown types fail closed. The packaged [schema](../services/api/src/brainoid_api/device_protocol.schema.json) must equal [the canonical schema](../specs/device-protocol.schema.json); a test enforces parity. Only hello followed by heartbeat is currently accepted inbound. Server-direction frames and future command/notification requests are refused until their owning tickets register their handlers. A heartbeat's optional private-session ID and last-received sequence are telemetry and never select a watch or renew a private-session idle deadline. Hello capabilities never grant permission.

## Two different generations

The existing device document's `connection_generation`, the signed device identity, credential family, `DeviceBinding`, command `DeviceTarget`, and private-session records retain their existing **credential/authorization fence** semantics. IAM-08 permission shrink/revocation increments that fence and invalidates the original access and refresh family. A socket reconnect never modifies it or refreshes a credential.

The new `tenants/{tenant_id}/device_connections/{device_id}` document holds a separate **transport generation** in `generation`. This is the `connection_generation` carried on WSS frames. Each successfully authenticated hello allocates the next integer atomically, even across server instances. The record also holds an unpredictable connection owner ID, the original credential fence/family/epoch, online flag and lease expiry. No bearer, payload, hello cursor, or arbitrary watch path is stored. Disconnect only marks its own matching owner offline; it cannot delete or replace a newer connection. The generation counter survives clean close and lease expiry. Acquisition response loss still attempts owner-specific cleanup. Expired records are logically offline even if a crashed instance never wrote `online: false`.

Consumers must use both bindings. In BA-DEV-04/05, retain `ConnectionBinding.generation` for the socket and use `ConnectionBinding.identity.connection_generation` for existing credential/session/command authorization. Never substitute the wire generation into an existing DeviceTarget or silently upgrade an old command/session to a fresh identity. This additive storage change needs no credential migration. Existing credentials reconnect normally. Retain connection records across revisions to keep transport generations monotonic. The tenant lifecycle's existing recursive collection walk covers the new tenant subcollection. A rollback removes the WSS entrypoint but does not require rewriting credential records; a later rollout resumes the saved transport counter.

## Lease and revocation

Only an authenticated, current-generation heartbeat renews the 45 second lease. A heartbeat at or after expiry cannot resurrect it. A 15 second monitor checks the current signed access-token expiry, credential family, device/tenant state and independent authorization ledger, even when no client frames arrive. Each storage wait has a 5 second admission timeout: under a responsive event loop, allowing a preceding 5 second check, 15 second sleep, next 5 second check and 5 second close wait, the monitor closes within 30 seconds after a revocation/ledger failure becomes visible, below the 60 second design target. Three missed heartbeats make the lease expire at 45 seconds. Watch activity, unrelated frames and monitor checks do not extend it. Existing 15 minute access-token expiry and credential-family expiry remain authoritative.

Handshake acquisition and connection work carry a local monotonic deadline and cancellation/liveness guard. The guard is checked when a queued worker obtains capacity, on every transaction retry, after policy reads before a business callback, and before buffered mutations/response release. The gateway also observes peer disconnect during queued acquisition; another application frame before hello_ack is rejected. An operation which times out, is cancelled or observes its peer disconnect while queued cannot later acquire a new generation or start business work. Cleanup still drains SDK calls that already began and releases only its own connection ID; cancellation does not roll back a previously committed write.

New work uses `DeviceLeases.run(binding, callback, admit=...)`: credential/current-generation reads and callback writes are in the same transaction, so a concurrent newer hello conflicts with an old transaction. The callback may be retried and must have no external effects. Submitting a callback to a worker queue does not admit its transaction. The gateway passes its no-I/O request guard; repository callers without a socket retain the existing trusted in-process contract. A transaction admitted before a newer hello may already have committed; this boundary does not retract bytes or effects already admitted. Downstream command execution still requires the separate DEV-05 claim/grant contract.

## Delivery and cleanup

`DeviceGateway(hooks=...)` is a server composition point. Each async context manager receives a `DeviceConnection` whose immutable tenant/device identity comes from the authenticated token. Watch adapters derive their query from that binding, own their watch and task handles, and close/join them in their context finalizer. No client input can register hooks or select tenant/device watch paths. The default runtime registers none until DEV-04/05 are implemented.

`enqueue(Delivery(kind, load))` runs on the event loop; a Firestore thread callback must marshal into that loop. The bounded queue holds at most 16 loader callbacks. Overflow closes the connection; slow ASGI sends time out after 5 seconds. A loader receives the guarded transaction and binding and must check resource/session/output policy and tenant/device ownership there. It must load current data, not return a private body cached from an earlier watch event. The gateway checks the original credential and current lease in that same transaction, validates the frame, and retains no-I/O deadline guards through the thread-to-event-loop handoff. This hook is trusted server code; business-resource authorization remains the loader's responsibility.

Disconnect, cancellation, invalid frames, hook errors, backpressure and monitor failures close the socket first, cancel/join all owned async tasks, run hook finalizers, drain all outstanding worker-thread operations, then attempt lease CAS release. Timed-out worker operations are shielded and retained until completion so late writes/errors cannot escape cleanup. The storage SDK's completion bound still governs final cleanup duration; Python cannot forcibly cancel a running SDK thread. Failed cleanup leaves an expiring lease and emits only a fixed event. Hooks must be cancellation-cooperative and complete their finalizers; no third-party watches are installed by this ticket.

## Logs and local validation

Application events contain a fixed outcome, never headers, query, frames or exception details. Uvicorn's default WebSocket transport logs URLs even with HTTP access logs disabled. The supported entrypoint therefore selects `DeviceWebSocketProtocol`, which replaces each connection's transport logger with a content-free event sink before receiving traffic, also covering malformed handshakes/UTF-8 and rejected query credentials. Custom server launchers must select the same protocol, 64 KiB maximum, disabled compression and content-free logging; directly launching Uvicorn with its defaults does not provide this logging contract. Upstream ingress access-log policy is a deployment responsibility.

AnyIO shielded cleanup also handles request-level cancellation scopes. Runtime dependencies explicitly declare the already locked anyio 4.15.1 (MIT), jsonschema 4.26.0 (MIT) and websockets 17.3 (BSD-3-Clause); no versions or cloud privileges were added. The schema is an installed package resource and does not depend on the checkout or working directory. Local tests cover fake-clock lease/revocation, real loopback WebSocket framing/logs, resource cleanup/faults, and official Firestore Emulator concurrent instances. Full credential/device regression tests retain IAM-07/08 guarantees. Physical Pi, Cloud Run failover/latency, proxy log policy and production revocation timing remain unmeasured.
